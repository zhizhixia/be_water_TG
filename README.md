面向**已取得群管理员明确许可**的 Telegram 群的本机辅助工具：低频参与讨论、每日签到、按明确规则参与抽奖，并提供一个只在本机打开的中文控制台。

> **这是预发布，不是稳定版。**
> 本版本对应 GitHub 标签 `v2.0.0-rc.1` 的 Release，发布时勾选为预发布（prerelease）。仓库当前的 Latest 仍是旧版 `v1.0.1`，不要下错。

## 安装（Windows 64 位）

不需要安装 Python。

1. 下载 `BeWaterTG-win64.zip` 和 `SHA256SUMS.txt` 到同一个文件夹。
2. 校验 ZIP（可选但建议）。在 PowerShell 中执行：

   ```powershell
   Get-FileHash .\BeWaterTG-win64.zip -Algorithm SHA256
   ```

   把输出的完整十六进制串与 `SHA256SUMS.txt` 中对应行比较，忽略大小写，64 位内容一致才继续。
3. 解压整个 ZIP，得到 `BeWaterTG` 文件夹。路径可以含中文或空格。
4. 双击 `BeWaterTG\BeWaterTG.exe`。会弹出一个控制台窗口，显示 `http://127.0.0.1:5000`。
5. 用浏览器打开这个地址。控制台只监听本机回环地址，局域网和公网访问不到。

注意：

- 必须保留 `BeWaterTG.exe` 同目录下的 `_internal` 等全部文件。**只拷贝一个 EXE 是跑不起来的。**
- 移动程序时整个 `BeWaterTG` 文件夹一起移动，不要只挪 EXE。
- 当前构建没有做代码签名。Windows 若提示“未知发布者”，请先核对下载来源和 SHA-256 再决定是否运行。
- 关闭控制台窗口 = 结束本机服务；只关闭浏览器页面则不会停止后台任务（见“日常操作”）。

## 第一次使用

**打开页面、填写设置、保存设置都不会连接 Telegram。只有点击“开始”才会连接账号。**

第一次打开时如果还没有填写 API ID，界面会默认停在“连接与设置”。这不是配置向导，需要你按下面顺序逐页填写并保存。

七个页面是：运行概览、授权群与任务、普通参与、签到与抽奖、AI 与消息库、安全与审计、连接与设置。

### 1. 连接与设置

- **Telegram API ID / API Hash**：在 <https://my.telegram.org> 用你要运行的账号申请。API Hash 是 32 位十六进制字符。
- **手机号**：该账号绑定的号码，必须带国际区号；例如中国号码以 `+86` 开头，后面接完整手机号。
- **代理**：可选。填了地址就要同时填端口；不用代理就把地址留空、端口保持 0。
- 保存后 API Hash 不再回显，只显示“已设置”。留空保存表示保持原值，不会清空。
- 要清除已保存的 API Hash，必须先停止任务。
- “工作时段”也在这一页。启用后只在两个上海时间窗口内动作；窗口外只观察，不发送聊天、签到或抽奖。

### 2. 授权群与任务

- 填 `@group_name` 或 `https://t.me/group_name`，一行一个，点“添加到待保存列表”，再点“保存群组与任务”。
- 只能填**这个账号已经加入**的群。程序不会自动加群、不会自动发现群，也不会为了识别链接而进群。私密群邀请链接只有在账号已加入时才能识别。
- 每个群单独设置：
  - **已获许可**：必须由你确认已取得该群管理员许可，否则不能开始。
  - **聊天**：普通参与，新添加的群默认开启。
  - **签到**：新添加的群默认关闭。
  - **抽奖**：新添加的群默认关闭。
- 至少要有一个群勾选“已获许可”，并且至少启用一个任务，才能开始。
- 运行期间不能增删群；要改群列表，先停止任务。

### 3. 普通参与

这一页是全局策略，所有开启聊天的群共用：

- **每群每日文本上限**：普通参与和签到共用这个额度；额度是上限，不要求每天发满。
- **冷场阈值（分钟）**：群内多久没有新消息算冷场。
- **问题参与概率 / 讨论与冷场概率**：命中后仍要经过相关性、额度和暂停状态检查，不保证一定发言。
- **发送前等待下限 / 上限**：形成候选后先等待，再复核消息是否变化。

程序不会追着每个新消息发言；连续两个完整冷场窗口无人回应，该群普通参与暂停到次日。

### 4. 签到与抽奖

- **签到**：只发送精确的顶层文本“签到”。每群每个上海自然日最多一次已发出的尝试；失败、超时或结果未知都不会当天重发。签到失败不会连带停止普通聊天。
- 明确投诉或管理员警告会暂停对应群；Telegram 限流和数据库故障会影响全账号。这些共享保护不能用另一个功能绕过。
- **抽奖扫描**：按设置间隔扫描授权群。冷启动只建立普通消息基线，不追溯历史；可以额外检查上海当日仍置顶的消息。
- **额度与间隔**：每群每日抽奖上限、全账号每日抽奖上限、抽奖动作之间的等待区间。
- **自动执行范围很窄**：只处理原消息中唯一、明确的参与按钮，或原消息里写明的固定短文本（不超过 32 个字符）。发布者必须是群主、管理员或机器人，且权限查询成功。
- 以下情况一律转人工，不自动点：外链、关注、转发、私聊、加群、支付、验证码、投票、多个参与按钮、正文含额外条件、截止时间无法确认、发布者权限未知。
- 抽奖结果未知时会冻结该群抽奖，不自动重试、不退还额度。**“已执行”只表示动作发出去了，不等于中奖。**
- “打开原消息”只生成 Telegram 链接，不改变提醒或冻结状态；浏览器拦截弹窗时只提示，不会把记录标成已查看。
- “标记已查看”只关闭待处理提醒，不解冻，也不改外发账本或额度。要恢复冻结的抽奖，需要在“运行概览 → 需要处理”里输入“确认恢复”。
- “清理历史”只能在任务停止后使用，按上海发现日期删除，且可能让旧抽奖再次被发现；执行前有二次确认。

### 5. AI 与消息库（可选）

- AI 默认关闭。启用需要同时勾选“已同意向配置的服务发送必要群聊文本”，并填写 API 密钥。
- 启用后会外发：最近群聊的正文和文本上下文。不会外发：图片/视频等媒体、Telegram 登录会话、Telegram API 凭据、数据库。
- AI 可以生成受限的聊天候选文本，也可以辅助判断消息类型和疑似抽奖；它没有外发执行权，不能生成或修改抽奖动作参数。抽奖动作只从原消息解析。
- AI 主动返回 `[SKIP]` 时不会改发 TXT；只有 AI 服务调用失败，才会降级到消息库。
- 撤销同意或关闭 AI 后，不再发起新的模型请求。已经发到服务商的请求无法撤回。
- “AI 与消息库”页可以编辑 TXT 消息库：一行一条；新版格式行内的逗号会保留（旧版逗号分隔文件首次加载时会按逗号拆成多条）。保存时会核对加载时的文件版本；文件被其他页面改过，会要求重新加载，不会覆盖别人的修改。
- 没有配置 AI 也可以使用聊天（改用消息库文案）、签到和抽奖。

### 6. 开始与账号认证

1. 点顶部的“开始”。
2. 第一次登录会要求验证码；如果账号开了两步验证，还会要求密码。按页面提示在“账号认证”区域提交。
3. 验证码和密码只用于当前这次登录，不写入配置、数据库或日志；等待 180 秒，连续 3 次错误会停止，需要重新点“开始”。
4. 同一账号 + 同一数据库只允许一个后台实例。新旧两版也共用本机互斥锁，不能同时运行。

## 日常操作

- **暂停**：阻止新的自动动作，不删除数据。恢复后按当前配置继续观察。
- **停止**：取消等待、断开账号，不删除任何数据。
- **关闭网页 ≠ 停止**：后台任务还在跑。页面顶部会明确提示“关闭网页不会停止后台任务”。要真正结束，先点“停止”，或关闭控制台窗口/结束 `BeWaterTG.exe` 进程。
- 正常退出应先点“停止”、等到“已停止”，再关闭控制台窗口。强制结束进程不能撤回平台已接收的动作，重启后须先核对未知结果提醒。
- 页面断线重连后会重新读取快照；不要因为页面打不开就认为任务已停。
- 运行中保存配置：单群开关与撤销 AI 同意立即生效；其他参数在停止并重新开始后生效，顶部会提示“有已保存但尚未应用的配置”；账号、代理、群列表必须先停止才能保存。

## 运行数据放在哪里

所有运行数据都在当前 Windows 用户的本地应用数据目录，**不在程序目录里**：

```text
%LOCALAPPDATA%\BeWaterTG\
├── config\settings.json              新版完整配置（账号、群、策略、AI）
├── config\.env                       旧版配置，保留原样，只作首次导入来源
├── config\messages\                  可编辑的 TXT 消息库
├── state\be_water.db                 SQLite 状态库（旧表保留，新增 bw_ 表）
├── session\sender_session.session    Telegram 登录会话
├── logs\bewater-v2.log               2 MB 轮转日志，保留 3 份备份
└── backups\                          数据库升级前备份、迁移标记与升级摘要
```

- `%LOCALAPPDATA%` 通常是 `C:\Users\<你的用户名>\AppData\Local`。替换或升级程序目录不会影响这里的数据。
- **session 文件等同于登录凭据**。拿到它的人可能可以操作你的账号。不要上传、不要发给别人、不要放进公开网盘；怀疑泄露时，先在 Telegram 的“设备”里终止该会话，再删除文件重新登录。
- `be_water.db` 是单文件数据库，不要让其他程序同时写它。日志是中文运行摘要，不记录认证输入、API 密钥或按钮回调原文；但数据库里有群标识、标题和操作记录，仍按私密资料保管。

## 从旧版升级

升级前务必做完整备份（见“备份与恢复”）。升级只替换程序目录，运行数据仍在 `%LOCALAPPDATA%\BeWaterTG`。

1. 在控制台点“停止”。
2. 关闭控制台窗口，确认后台已退出。
3. 复制整个 `%LOCALAPPDATA%\BeWaterTG` 到安全位置。
4. 用新版本的完整目录替换旧程序目录（不要只换 EXE，不要把新旧文件混在一起）。
5. 启动新版。每次正式启动都会先执行一次受控的升级准备。

升级时会做什么、不会做什么：

- 旧 `config\.env` 不覆盖、不删除；新版保存只写 `config\settings.json`。
- 旧配置中能识别的字段会作为首次初始值读取，但**旧授权群需要你重新勾选“已获许可”**，程序不会替你确认许可。旧版全局的签到/抽奖开关会作为初始值带入；新添加的群仍然默认关闭签到和抽奖。
- 旧数据库在固定位置时继续使用；启动后会在同一个库里新增 `bw_` 前缀的新表，旧表保留不删。
- 旧 `.env` 里 `MESSAGE_FILES` 和 `messages.txt` 引用的 TXT 会尽量导入 `config\messages`；无法安全导入的会计入 `backups\v2-upgrade-report.json` 的计数，需要你自己检查或重填。
- 程序**不会**把所有旧状态、旧配置、旧消息自动搬完，也**不会**替你生成整个运行目录的备份。升级前请自己备份。
- **旧自定义数据库路径**：如果启动时提示迁移阻断，按提示保留源文件，把旧数据库人工复制到
  `%LOCALAPPDATA%\BeWaterTG\state\be_water.db`，再重启；不要删除或覆盖源文件。
  如果你以前在旧 `.env` 里把数据库改到过别处，但新版没有给出阻断提示，新版仍然只读固定位置的 `state\be_water.db`；请先备份，再手动把旧库复制过去。目标位置已有数据库时不要直接覆盖，先确认哪一份是你要保留的。
- 阻断状态记录在 `backups\migration-state.json`。不要删除它来“绕过”阻断；先处理数据库冲突。

### 降级与回退

- 新版已经在旧库上增加了 `bw_` 表。**不要拿升级后的数据库去覆盖旧备份**，也不要指望旧版能理解新版表。
- 回退时使用“升级前的完整运行目录备份 + 旧程序目录”，并且先停止、退出所有实例。
- **不要新旧两版同时运行**：它们共用本机互斥和同一份运行数据，同时开会导致锁冲突或状态混乱。
- 降级不能保证无损。升级前的完整备份是唯一可靠的回退依据。

## 备份与恢复

备份的对象是整个运行目录，不是程序目录，也不是单个数据库文件。

1. 控制台点“停止”。
2. 关闭控制台窗口/结束 `BeWaterTG.exe`，确认后台任务已退出。**只关网页不算停止。**
3. 复制整个 `%LOCALAPPDATA%\BeWaterTG` 到备份位置。
4. 恢复时：先停止并退出，再用备份目录整体替换 `%LOCALAPPDATA%\BeWaterTG`，最后启动。

说明：

- `backups\` 可能包含旧库结构升级前自动生成的 `before-v2-*.sqlite` 一致性备份，以及迁移标记和摘要；它**不是整个运行目录的定期备份**，不能代替配置、session、消息库和数据库的完整备份。
- 备份里包含 session 和群数据，按敏感资料保管；不要提交到 Git，不要公开分享。
- 升级前、改账号前、换电脑前，都建议单独留一份完整备份。

## 排障

**浏览器打不开 `127.0.0.1:5000`**

先看控制台窗口是否还在。窗口关了服务就停了。若提示端口不可用，通常是 5000 被其他程序占用，或已有一个 BeWaterTG 在运行；关闭占用程序或已有实例后重试。程序不会自动结束其他进程。

**一直显示未配置**

访问 <http://127.0.0.1:5000/api/health>，返回 `configured: false` 表示还不能开始。需要同时满足：有效的 API ID、32 位 API Hash、带国际区号的手机号、至少一个“已获许可”且启用任务的群；若启用 AI，还需密钥和文本外发同意。填完要逐页点保存。

**保存时提示“配置已变化”**

另一个标签页或窗口改过配置。刷新页面、重新加载后再保存，不要连续强行提交。

**升级后看不到旧群或旧记录**

先确认旧数据库是否在固定位置 `%LOCALAPPDATA%\BeWaterTG\state\be_water.db`。如果旧版曾自定义数据库路径，按“从旧版升级”里的说明先备份再复制。不要删除 `backups\migration-state.json`。

**签到当天没发**

当天已经有过一次已发出的尝试（包括失败或结果未知）就不会重发。再检查：该群签到开关、工作时段、文本额度、群是否被人工或安全暂停。单独的抽奖结果未知冻结只影响抽奖，不应误认为它关闭了签到。

**抽奖没有动作**

看“签到与抽奖 → 抽奖记录与提醒”的原因列。常见原因是需要人工、发布者权限未知、条件不明确、已过截止、额度不足或该群抽奖被冻结。冻结后要人工输入“确认恢复”；“标记已查看”不会解冻。

## 能力边界与验证状态

能力边界：

- 只处理你显式配置、且已获管理员许可、账号已加入的群；不自动加群，不隐藏自动化身份，不绕过 Telegram 风控。
- 不保证中奖，不保证每条发言都相关，不保证签到一定被群机器人接受。
- 没有首次配置向导；没有“自动下载/修复依赖”；关闭网页不会停止服务；不会自动加入群。
- AI 需要你自备兼容 OpenAI 接口的服务和密钥，费用与输出质量由你承担。

验证状态（截至本 RC）：

- 本轮做过：新版离线测试、浏览器流程、独立用户路径验证，以及隔离数据目录下的 Windows EXE 启动/健康检查/单实例/端口释放冒烟。测试数量以实际命令输出为准，本说明不写死数字。
- **没有做**：真实 Telegram 账号登录与群内动作、真实 AI 服务调用、生产数据迁移验收，以及其他电脑、杀毒软件、代码签名环境下的验证。
- 旧版测试存在默认相对路径 `state/be_water.db` 写库的风险，仅隔离 `LOCALAPPDATA` 不足以保护已有旧库。**旧版测试必须在干净克隆或不含真实 `.env`、session、数据库的独立源码副本中运行。**
- 本机源码目录下的旧库已出现保护差异，业务影响尚未完成只读对账。本 RC 不修复、不清理该旧库，也不表示该差异已经解决。
- 因此请先在测试账号、测试群里小范围观察，确认行为符合预期后，再用于有价值的群。

## 从源码运行（开发者）

要求：Windows、Python `>=3.11,<3.12`（推荐 3.11）、[uv](https://docs.astral.sh/uv/)。

```bash
# 安装新版全部依赖（runtime / dev / build）
uv sync --project rewrite --all-groups

# 启动新版控制台（二选一）
# 1) 仓库根目录双击 start-v2.bat
# 2) 命令行：
uv run --project rewrite --frozen --group runtime python rewrite/main.py
```

- 新版源码、测试和构建脚本都在 `rewrite/`；根目录的 `main.py`、`run.bat` 是旧版入口，不是新版。
- 新版测试（匿名临时目录，禁止真实外部连接）：

  ```bash
  uv run --project rewrite --all-groups pytest -c rewrite/pytest.ini rewrite/tests -q
  ```

- Windows 构建（生成完整目录 EXE、ZIP 和 `SHA256SUMS.txt`，并执行本机回环冒烟）：

  ```bash
  uv run --project rewrite --frozen --all-groups python rewrite/build.py
  ```

  构建产物在仓库内的私有构建目录，不提交、不随仓库分发；发布只取审计过的 ZIP 和校验文件。
- 推送 `v2.*` 标签时，CI 会运行新旧测试并构建新版，生成预发布草稿，由维护者核验后再公开。以 Actions 的实际结果为准。
- 更细的源码结构、测试与构建说明见 <https://github.com/zhizhixia/be_water_TG/blob/main/rewrite/README.md>。

## 旧版说明（仅兼容/回退）

- 旧版入口是根目录的 `run.bat` 和 `main.py`，属于 v1，仅用于对照和回退；不要把它当成新版启动方式。
- 旧版的功能、配置字段和行为与新版不同，不要把旧版 `.env` 的说明直接套到新版控制台，也不要两版同时运行。
