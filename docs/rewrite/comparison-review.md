# 新旧实现只读评价与主代理复核

## 结论

两名只读子代理分别审工程质量和需求符合度，均认为**新版更适合本次批准的目标，但不应在未经受控验证时直接开启真实外发**。这不是整体性能基准，也不是“新版已经比旧版成熟”的证明。

新版优势：三类任务解耦、每群开关、统一预写与紧前门禁、typed peer边界、配置保值与版本冲突保护、自然参与与新旧候选区分。旧版优势：更充分的历史测试/交付资产，Settings/GroupState等类型模型较明确。新版目前仍大量使用受校验字典和字符串状态；没有宣称完整静态类型检查通过。

子代理没有实施任何改动，没有登录平台。所有修订仍由主代理完成。初次冻结评价输入在 `.hermes/rewrite/review-input/`；**它代表审查时版本，不代表之后的修订版**。后续修订由主代理独立验证，没有冒称子代理再次批准。

## 已确认并修订

1. **已恢复签到重复拉取**：反例实际观测重复调用4次，根因是RECOVERED判重在拉取之后。判重前移，并把同日SENT/UNKNOWN/FAILED/BLOCKED等终态一并跳过；次日重新处理。相应测试也确认只写一次恢复审计，不影响聊天。
2. **人工解冻重启失效**：反例复现重启重新冻结。recover现只处理本次CALLING/EXECUTING中断，事务内创建冻结并转UNKNOWN，不重新激活历史已查看提醒。保留旧UNKNOWN事实和额度；旧版导入的UNKNOWN仍保守冻结一次，人工确认后不重复导入。
3. **管理员警告词遗漏**：补回“移出群/管理员提醒”；角色查询过滤和最终判定共享同一词表。普通成员同样文字不误当管理员警告。
4. **轮询过密**：上下文仅首次读取，后续增量更新有界内存；普通观察间隔30秒，有待发候选时按到期缩短。聊天开关关闭但仍有其他任务的群保留安全观察，这是共享安全所需，不能简单删掉。抽奖等待账号动作时隙期间不重复查询发布者。
5. **消息库并发覆盖**：revision检查、原子替换和返回值同一实例锁保护；真实双线程反例验证一个成功、另一个409。
6. **旧配置坏数字500**：转换失败变为字段级中文错误，不输出错误原值；健康仍返回configured=false。不会默默丢弃旧密钥或覆盖原dotenv，需修正明确指出的旧字段。
7. **callback确认语过窄**：额外认可“已参与”“参与成功，等待开奖”等明确确认；附加条件、跳转和含糊/空回应仍保守UNKNOWN，不进行额外动作。
8. **来源与展示**：来源进入真实账本；schema1→2先一致性备份，保留旧记录、未知旧来源留空。群行加入有效群链接与最近决策；人工暂停不再写成安全暂停；抽奖统计按实际进入调用的尝试计算，不把配额阻挡算成真实请求。

核心审查反例在修订前真实得到 `5 failed, 2 passed`，不是仅凭子代理描述认定问题。最终修订版 `84 passed in 4.13s`，门禁记录 `passed/test/full`。旧版tests目录另有 `512 passed, 80 warnings in 16.82s`（门禁范围标targeted，不冒称覆盖新版）。

## 需纠正或保留边界的子代理结论

- **“缺messages.txt所以打包失败”不成立**：脱敏评价包为了避免带私人消息文件而未包含TXT，也遗漏了构建回执。这只能证明评价范围中缺文件。主工作树已有实际构建与ZIP/EXE冒烟证据；主代理再次完整重建、读回CRC/摘要。此次评价材料准备确有缺陷，方法已补入委派规范。
- **“Windows构建未验证”不成立**：子代理未取得主代理已有构建回执，不代表未构建。本报告以实际工具输出为准，不把静态猜测放在已执行结果之上。
- **“旧last_outbound_id漏迁移”缺少依据**：旧GroupState并没有该字段，实际字段last_message_id不能在未核实语义时冒充本人外发ID。新版使用平台上下文及新账本中的本人外发ID，不凭名称猜测迁移。
- **审计/去重/冻结不随抽奖清理一起删除**是保守策略：尤其冻结不能用清理绕过人工确认。没有新增自动压缩/归档机制，长期磁盘规模仍需观察。
- **首次使用**保留单页设置引导，不恢复旧多步向导或Flet；界面沿用既有深色系统。两套布局没有在实现前选定，属于已披露的流程偏离，不伪造批准记录。
- 四个同口径案例只说明配置开关、固定文本、分页、七日去重场景；固定文本包含新需求，不把它全部包装成旧版缺陷。

## 交付与剩余风险

新版可作为本机试用候选，不能称真实业务验收通过。已实际验证：匿名真实网页/后台线程/业务/SQLite闭环，Windows批处理，EXE健康/静态资源/单实例/进程退出，ZIP敏感文件排除与CRC/SHA256。

未执行真实账号登录、发送、签到、按钮回调、AI请求、真实身份映射与生产迁移。旧入口不自动替换。旧版不认识新版bw_事实，正式使用后不能把“还保留旧程序”理解成可无风险交替运行。

根AGENTS新版补充因审批超时被拦截，未重试或绕过；根README与rewrite/README已说明新旧入口。其余数据保护例外、每项证据及视觉流程偏离见 `acceptance-results.md`。
